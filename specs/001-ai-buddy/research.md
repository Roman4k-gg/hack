# Исследование и выбор решений

## LLM

| Вариант | Плюсы | Минусы | Решение |
|---|---|---|---|
| OpenAI-совместимый API через свой httpx-клиент | Одна зависимость, любой провайдер (OpenAI, OpenRouter, Ollama, vLLM), легко подменить в тестах | Нет готового fallback между провайдерами | **Выбрано** |
| LiteLLM | Много провайдеров из коробки, fallback | Тяжёлая зависимость, сложнее отлаживать | Отказались |
| Нативные SDK провайдеров | Полный функционал | Привязка к одному провайдеру | Нет |

Требование к модели — поддержка **tool calling**. Целевая модель на демо — `gpt-4o-mini`
(дёшево, быстро), temperature 0.2, max_tokens 800. Без ключа работает сценарный mock.

## Mock LLM

Сценарный mock (`ai/app/providers/mock.py`) выбирает инструмент по ключевым словам и строит
ответ из результата инструмента. Так демо и CI работают без сети, а тесты проверяют весь
путь: агент → инструменты → core → SSE. Записанные ответы настоящей LLM отклонили — они
ломаются при любом изменении промпта.

## Поиск по базе знаний (RAG)

| Вариант | Плюсы | Минусы | Решение |
|---|---|---|---|
| Поиск core (`ILIKE` + ACL) + ключевые слова и стемминг в AI | ACL в одном месте, просто, объяснимо | Нет семантики («ноут» ≠ «ноутбук») | **Выбрано** |
| Эмбеддинги + pgvector в core | Семантический поиск | Время, ключ на эмбеддинги, ACL нужно повторить в векторном поиске | Stretch |
| Эмбеддинги в AI-сервисе | Независимость от core | Дублирование данных и ACL | Нет |

Golden set показал проблему морфологии: «релизы» не находило «релизов». Решение — отрезать
окончания русских слов перед запросом в core и ранжировать документы по числу совпадений.
После этого golden — 20/20.

## MCP

- SDK `mcp` 2.x, класс `MCPServer`, транспорт Streamable HTTP, stateless, JSON-ответы.
- JWT пользователя передаётся в заголовке `Authorization` каждого запроса; MCP-сервер
  проверяет его сам и вызывает core от имени пользователя.
- stdio-транспорт отклонили: в нём нет естественного места для JWT пользователя.
- Если MCP недоступен, агент вызывает core напрямую с теми же правами — демо не падает.

## Подтверждение действий

| Вариант | Решение |
|---|---|
| Модель получает `confirmation_token` и передаёт его в `create_*` | Отклонено: injection может заставить модель отправить заявку |
| Агент хранит токен сам, модель вызывает `create_*` без аргументов, только в следующем ходе | **Выбрано** |
| Подтверждение кнопкой на фронте | Хорошо, но требует отдельного эндпоинта; можно добавить поверх |

## Защита от prompt injection

Эвристики на регулярных выражениях ловят только явные атаки, поэтому они **не блокируют**
запрос, а предупреждают модель и пишутся в лог. Основная защита — архитектурная:
права из JWT, подтверждение мутаций, токен скрыт от модели, блок действий после
подозрительного документа.
