# Спецификация продукта · AI-buddy

**Кейс:** Hack&Change 2026, Авито — «AI-buddy: ИИ-наставник для стажёров»
**Версия:** 1.0 · **Статус:** реализовано и проверено на демо-стенде

## 1. Задача

Стажёр приходит в новую команду и тонет в чатах, доступ��х и документах. AI-buddy —
единая точка входа: отвечает на вопросы о команде и инструментах, ведёт по плану
адаптации и выполняет организационные действия от имени стажёра — строго в рамках
его прав.

## 2. Пользователи и роли

| Роль | Что получает |
|---|---|
| Стажёр | карту адаптации, ответы с цитатами, чат с AI, заявки на отгул и доступы |
| Наставник | карту адаптации своих стажёров, метрики прогресса, блокеры и просрочки |
| Руководитель | то же плюс сводка по своей команде |
| HR | сводка по всем стажёрам, контентные дыры в базе знаний |
| Администратор | всё выше + фиче-флаги, аудит |

## 3. Ключевые сценарии

### S1. Мой маршрут
Стажёр логинится и видит карту адаптации: этапы (Неделя 1 → Неделя 2 → Месяц 1),
пункты со статусами, прогресс и «следующий шаг». Пункт можно перевести в работу,
закрыть или заблокировать с причиной; прогресс сохраняется, действие попадает в аудит.

**Критерии приёмки**
- карта строится из PostgreSQL, а не из мока;
- статусы сохраняются между перезагрузками;
- «следующий шаг» указывает первый незакрытый обязательный пункт;
- повторная отправка того же статуса не создаёт лишних audit-записей;
- чужой пункт недоступен (403).

### S2. Спроси про команду и инструменты
Стажёр спрашивает «где взять доступ к Jira?». AI находит документ в базе знаний,
отвечает с цитатой, ссылкой, датой обновления и владельцем; при низкой уверенности
честно говорит «не нашёл» и предлагает эскалацию.

**Критерии приёмки**
- поиск учитывает права: документ другой команды не выдаётся;
- в ответе есть цитата со ссылкой на источник;
- устаревший документ (>180 дней) помечается;
- вопросы фиксируются, и наставник видит топ вопросов и контентные дыры.

### S3. Отгул
«Хочу отгул в пятницу» → AI показывает черновик (даты, тип, причина) и правила
политики → стажёр подтверждает → создаётся заявка со статусом `pending`, внешним id
и согласующим. Заявка сохраняется, видна в разделе «Мои заявки», попадает в аудит.

**Критерии приёмки**
- без подтверждения заявка не создаётся;
- токен подтверждения одноразовый и живёт 10 минут;
- повтор с тем же `idempotency_key` возвращает ту же заявку, а не создаёт вторую;
- заявка другого пользователя недоступна (403).

### S4. Доступы
Стажёр выбирает пакет доступов по роли → видит список систем с причиной и
согласующим → подтверждает → создаются отдельные заявки на каждую систему со
своим статусом.

**Критерии приёмки**
- пакет берётся из справочника, а не из кода;
- подтверждение одноразовое, повтор идемпотентен;
- у каждой заявки свой внешний id и статус.

### S5. Панель наставника
Наставник видит список своих стажёров: прогресс, успеваемость по дедлайнам,
блокеры с причинами, просроченные пункты, активность и топ вопросов команды.

**Критерии приёмки**
- наставник видит только свою команду, HR и админ — всех;
- «успеваемость» считается по пунктам с прошедшим дедлайном;
- стажёр не видит метрики команды (403).

## 4. Нефункциональные требования

| Требование | Как обеспечивается |
|---|---|
| Покрытие прикладного кода > 80% | `make coverage-gate`, порог 80% в CI |
| Отклик локальных операций < 1 с | локальные выборки из PostgreSQL, кеш react-query |
| Безопасность | JWT HS256, скоупы, object-level проверки, ACL документов, аудит |
| Воспроизводимость | `make up && make seed` с чистой базы, детерминированный seed |
| Наблюдаемость | структурные логи с `trace_id`, таблицы `audit_log` и `events` |
| Совместимость со стеком | Go + Python + PostgreSQL + Redis + React + TypeScript |

## 5. Что осознанно не входит

Реальные интеграции с Jira/Confluence/HR-системами (только имитации), эмбеддинги и
семантический поиск (лексика + чанки), дайджесты и AI-cron, handoff, панель
аналитики для HR, мобильная версия, обучение собственной модели.
